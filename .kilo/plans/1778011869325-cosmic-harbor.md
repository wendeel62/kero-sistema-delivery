# Plano: Instalar Vercel CLI

## Contexto
- Usuário quer instalar o Vercel CLI **globalmente** e como **devDependency** no projeto
- Já possui conta Vercel configurada
- Sistema: Windows (PowerShell)

## Passos

### 1. ~~Instalar Vercel CLI como devDependency do projeto~~ ✅ CONCLUÍDO
```powershell
npm i -D vercel
```
- ✅ Registra `vercel` no `package.json` como devDependency
- ✅ Garante versão consistente no CI/time
- ✅ Fica acessível via `npx vercel`
- ⚠️ Aviso: `tar@7.5.7` deprecated (dependência transitiva), 35 vulnerabilities reportadas — não bloqueia uso

### 2. Instalar Vercel CLI globalmente
```powershell
npm i -g vercel
```
- Disponibiliza o comando `vercel` em qualquer terminal/diretório
- Útil para deploys rápidos e administração geral

### 3. Verificar instalação
```powershell
vercel --version
```
- Confirma que ambos os métodos instalaram com sucesso

### 4. Fazer login na Vercel
```powershell
vercel login
```
- Abre browser para autenticação OAuth
- Selecionar o provider usado na conta (GitHub, GitLab, Bitbucket ou email)

### 5. (Opcional) Linkar o projeto
```powershell
vercel link
```
- Conecta o diretório local a um projeto existente na Vercel
- Cria/atualiza o arquivo `.vercel/` com as configurações do projeto

### 6. Adicionar `.vercel/` ao `.gitignore`
O `.gitignore` atual **NÃO** contém `.vercel/`. Adicionar a entrada para evitar commit de dados locais:
```
# Vercel (local project config)
.vercel/
```

### 7. Adicionar script de deploy ao `package.json` (opcional)
Adicionar script `deploy` para facilitar deploys via npm:
```json
"deploy": "vercel --prod",
"deploy:preview": "vercel"
```

## Observações
- Para CI/CD, usar `VERCEL_TOKEN` como environment variable em vez de login interativo
- O `vercel` como devDependency garante que o CI use a mesma versão do CLI
